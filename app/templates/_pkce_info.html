🔐 Comprendre PKCE (Proof Key for Code Exchange)

PKCE protège le standard flow contre l'interception du code d'autorisation, en particulier pour les clients publics (sans client_secret).

  • code_verifier — chaîne aléatoire (43 à 128 caractères) générée par le client, gardée secrète, jamais transmise lors de la redirection initiale.
  • code_challenge — empreinte SHA-256 du code_verifier, encodée en base64url (méthode S256). C'est elle, et non le secret, qui part dans l'URL d'autorisation.

Déroulé du flow :

  1. Le client envoie code_challenge et code_challenge_method=S256 à l'endpoint /auth.
  2. Keycloak associe ce challenge au code d'autorisation qu'il va émettre.
  3. À l'échange du code (POST /token), le client transmet cette fois le code_verifier en clair.
  4. Keycloak recalcule SHA-256(code_verifier) et vérifie qu'il correspond au code_challenge reçu à l'étape 1.

Un attaquant qui intercepterait le code d'autorisation (logs, historique navigateur, redirection mal sécurisée…) ne peut pas l'échanger contre un token : il ne connaît pas le code_verifier, resté uniquement en mémoire côté client d'origine.
